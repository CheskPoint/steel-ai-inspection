# 部署运维

本地网页为 localhost:3000，后端为 localhost:8000，接口文档为 localhost:8000/docs，不混用 localhost 与 127.0.0.1。GitHub 更新不会自动更新独立服务器上的网站；需在服务器拉取代码、构建并重启服务。

启动见快速启动。前端构建使用 `npm ci && npm run build`，`frontend/next.config.ts` 生成 `dist/standalone/`，可用 `HOST=127.0.0.1 PORT=3000 node dist/standalone/server.js` 运行。后端需要 Python 与 best.pt，可用 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers` 运行；前端无法独立替代推理和业务服务。

公网部署建议由反向代理在同一 HTTPS 域名提供两项服务：`/api/v1/` 和 `/health` 转发至后端 8000，其余路径转发至前端 3000。代理需传递原始 `Host` 与 `X-Forwarded-Proto`；后端仅监听回环地址。构建前端时设 `NEXT_PUBLIC_API_BASE_URL=https://<域名>`，后端运行时设 `STEELVISION_ALLOWED_ORIGINS=https://<域名>`。两个值的主机名必须一致，且前端环境变量在构建时写入客户端代码，改值后需重新构建。

全新数据库上线前，给后端设置 `STEELVISION_INITIAL_ADMIN_PASSWORD` 为随机强密码。此变量只在第一次初始化数据库时使用；已有账号要在登录后从设置页面修改密码。密码不要写入仓库、Shell 历史或进程命令行。先以仅本机可访问的服务验证登录和模型，再开放公网入口。

备份前停后端，整体复制 backend/data（含 camera.key）。更换模型前备份 best.pt 和 evaluation.json；评估证据与权重指纹不符时指标不可用。

CPU 串行推理的验证批次耗时不等于产线 FPS；采集、排队、网络、NMS、绘图和归档会增加延迟。实体 RTSP、厂商 SDK、PLC/MES 和现场标准需单独验收。Cloudflare 模板保留，未验证线上 GPU 或共享存储部署。
